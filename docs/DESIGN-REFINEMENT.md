# Mirrai 官网 · 设计精进定案

> 版本 v1.3.1 · 2026-11-17 · 五轮问答定稿（修订记录见文末）
> 配合《项目计划书》《执行书》使用：信息架构、九屏内容、伦理口径不变；本文件只改**世界、节奏、高潮、物件感**。
> 品味判断：现有色盘、字体、纸纹、暖光、文案语气都成立，不要推倒重来。缺的不是另一套视觉系统。

---

## 1. 缺什么（诊断）

现站味道对，但首页九屏几乎都是同一骨架：

**kicker → 大标题 → 淡色正文 → 卡片 / 占位**

色盘、字体、纸纹、暖光都在；计划书里的「纸与信」「时间的痕迹」「对话的形态」更像被贴了标签，而不是一封真的信、一段真的对话、一间夜里的房间。

感到缺的是这三件（同时成立，不是三选一）：

| 缺 | 含义 |
|---|---|
| **物件感** | 应该像走进一间房、摊开一封信，而不像一个做得很克制的产品官网 |
| **高潮** | 九屏力度被均分；毕业 / 告别没有把人推下去 |
| **节奏** | 每屏同一套排版，滚下去像在翻相同的布局模板 |

**明确不是主因**：截图 / 录屏尚未就位会造成空，但不是这次精进要解的味。截图以后嵌进「相纸」，不作为主设计任务。

## 2. 世界（一句话）

打开官网，是进一间夜里的房间：镜头落到书桌，桌上有一盏灯、一封信、一段停住的对话。凑近信纸之后，才进入现在这套界面。读完，回到房间，灯灭。

品牌里曾经叠了太多隐喻（信、灯、镜子、消息痕迹、时区）。**主物件定为书桌**；信是桌上的主件，对话痕迹与时钟是桌上的配角。镜子 / 对望留给 logo，不再跟房间抢戏。

**房间与书桌要写实**：不用插画。房间是在 Blender 里搭出来的一个三维场景（v1.3 起），所有画面都从它渲染，见 §6 与 §11。禁区照旧：无人像、无剪影、不做灵异光影。

### 主题规则

房间是一个真实的夜晚，**不随明暗主题切换**：

- 进门镜头、Hero、第三幕回到房间——永远是夜，文字用固定的夜色 token。
- 第二幕桌面与软页**跟随主题**：夜 = 灯下的深色木桌；纸 = 白天的浅色桌面与纸。
- 亮色主题下就是「夜里的房间 → 白天摊开的纸 → 回到夜里」，不再另做一套白天房间。

## 3. 与计划书的关系

| 仍按计划书 | 按本文件改 |
|---|---|
| 九屏要讲的内容、中英两套文案口径 | 九屏不再视觉平级，改三幕 |
| `/download` `/ethics` `/about` `/privacy` `/blog` `/docs` 路由 | 软页仍在桌前「换纸」；文档与下载页出戏 |

不删屏、不另起文案体系、不把全站做成三维元宇宙。

## 4. 三幕结构

内容九屏都在，**体积和光线不再均分**。

### 第一幕 · 入室（灯是亮的）

人还在桌前：认出产品，认出自己。

| 原屏 | 在这一幕里做什么 |
|---|---|
| S1 Hero | 镜头落定的那一帧：书桌近景（灯 + 信）铺满，主标语、双 CTA、信任角标写在暗处 |
| S2 未竟之言 | **就是那封信**：一张信纸从 Hero 照片底部滑上来压住桌面。时间痕迹写在信里（停住的钟、没写完的结尾），不要三列统计数字 |

进门镜头（每次访问、必须可立刻跳过）发生在第一幕之前，见 §6。

### 第二幕 · 桌上摊开的几样东西

不是一篇长散文，也不是九次产品分节。**每屏必须换物件**，禁止再套 `kicker → 标题 → 网格`。

| 原屏 | 桌上的物件 |
|---|---|
| S3 怎么做到 | **三张拍立得**（上传 / 蒸馏 / 对话）。截图就位后嵌进相纸；未就位时是「还没显影」的相纸，不是虚线 SaaS 占位。P1 大厅不进首页（最多三张），只留 `/about` |
| S4 TA 不在的时候 | **四张纸条或四件小物**（信、暂时联系不上、先缓一缓、时区），不是四张圆角卡片 |
| S6 像不像 | **一张便条 / 一把尺子**（判别规则 + 保真之尺），不是流程砖块 |
| S5 毕业机制 | **高潮，也是掩卷的第一拍**。预录 demo 是纸条上的对话；随后字和物一起淡 |

S6 在叙事上给怀疑者看，可以紧挨毕业之前做蓄力，但视觉上仍是便条，不能做成大功能区把高潮冲掉。

### 第三幕 · 掩卷（开始回房间）

毕业带起灯灭。信任和下载**信息都在，不再做大屏**。

第三幕是**一个连续的场景**，不是三屏。顺序固定：

1. 毕业的对话纸条字迹淡去（M4）
2. 镜头退回房间远景，灯还亮着
3. 灯旁小字：信任四点 + 伦理入口 + 边界句（原 S7）
4. 桌上的信封：点开去 `/download`（原 S8）
5. 灯灭。黑暗里浮出尾句「有一天你不再需要它——那就是它做完了。」（原 S9）
6. 桌沿式页脚

尾句**全站只出现这一次**；毕业屏不再重复它。

页脚在灯灭之后以桌沿的方式出现，不要在高潮正中插入完整站点地图。

## 5. 房间管到哪

| 范围 | 怎么处理 |
|---|---|
| **首页 `/` `/en/`** | 完整三幕：进门、桌上物件、灯灭 |
| **软页**：`/about` `/ethics` `/privacy` `/blog`（及英文镜像） | 还在这张桌前，只是**换一叠纸**。同一盏灯、同一桌沿感；不要再套首页那套分屏演戏 |
| **工具页**：`/docs/*` `/download` | **出戏**。当工具用。纸纹和灯可以留一点回声（页眉、背景），不再进房间、不播镜头 |

首页信封 → `/download` 是「从桌上拿起信封走到工具台」，允许出戏。

## 6. 进门镜头

**每次进首页都播，必须能立刻跳过。**

时间轴（感觉，不是分镜脚本终稿）：

1. 夜里的房间（暗、远）
2. 落到书桌
3. 一盏灯、一封信在桌上
4. 凑近信纸
5. 溶进第一幕 Hero 文字

### 真的程度

**三维房间已落地（v1.3）。** 房间在 Blender 里搭，是所有画面唯一的源头：

- **静帧**（Cycles 渲染）：房间远景 · 灯亮（进门第一帧、第三幕）、书桌近景（Hero）、房间远景 · 灯灭（第三幕结尾）。灯亮 / 灯灭出自同一机位，逐像素对得上。第二幕铺在页面底下的桌面也是同一块木头。
- **进门镜头是真的三维**：光照烘进两张图集，网页里用 WebGL 实时画这间房，镜头从门口走到书桌前。落点与 Hero 照片是同一个机位，所以落定后溶进照片不跳。不依赖三维库：手写的渲染脚本构建后约 9 KB（gzip 后约 4 KB）。
- **横竖各一对机位**：手机竖屏不是把横幅裁一条，而是另一组构图——灯和信上下叠在画面上半，下半留给文字。
- **2.5D 推镜保留为退路**：不支持 WebGL2、开了省流量（或 2G）、加载失败、或期限内（桌面 1.5 s / 手机 1.1 s）没加载完，就把远景静帧推近再溶过去。同一条时间轴、同一个跳过键。
- **首屏文字让开信纸**：信纸在照片里的位置由场景导出（`scene.json` 的 `letterBox`），横屏时副标题与按钮行的右缘按它收住；书桌近景横向居中裁切，窗口比 16:9 更方时信纸也不会滑到文字底下。
- **不用**开门视频替代。

### 性能与可达（硬约束）

计划书性能预算仍然有效：LCP < 1.5s；Lighthouse 性能里程碑 ≥90、终验 ≥95。

因此：

- 跳过键揭开的是**已经在 DOM 里的正文**，不能等镜头播完才渲染 Hero。
- 镜头是盖在内容上的一层，不是内容的前置阻塞。
- `prefers-reduced-motion: reduce`：不放进门层——Hero 本身就是灯 + 信的静帧；第三幕不做滚动编排，按顺序平铺，灯灭用两张静帧表达。
- 手机也播进门，但时长更短（桌面约 4–5s，手机约 2.5–3.5s；跳过始终可见）。
- 三维层是锦上添花，不许拖累正文：它在远景静帧之后才加载（网格 + 两张光照图集共约 0.47 MB；竖屏和小屏用半尺寸图集，约 0.29 MB），超时即放弃并中止下载；镜头结束或被跳过后立刻释放 WebGL 上下文。
- 不存「看过就不再播」的偏好——用户已定每次都播；若以后要改，另开一轮，不在本定案里用 localStorage 偷关。

## 7. 第二幕物件语言

原则：**换物件 = 换节奏。** 不要用不同插画去填同一张卡片。

| 物件 | 材质感觉 | 注意 |
|---|---|---|
| 拍立得 | 相纸白边、轻微倾斜、叠放 | 最多三张；不要做成功能三栏 |
| 纸条 / 便条 | 手边随手写下的尺寸，不对齐网格 | 四态可以错落，不要 2×2 等大 |
| 尺子 / 保真之尺 | 一条可度量的物，不是四枚 badge | 数字是尺子上的刻度，不是 KPI |
| 对话纸条（demo） | 像从本子上撕下来的一段对话 | 保留「演示数据」标注；控件做成就在纸条下沿，不要做成播放器皮肤 |
| 信封（下载） | 可拿起的一件东西 | 主 CTA 仍指向 `/download` 或 `/go/*` 口径不变 |
| 灯 | 第一幕亮、第三幕灭 | 暖光仍克制：只照桌面，不做大面积色块 |

时间痕迹、时区、消息条，全部降为桌上的配角，不再单独开一节「设计系统展示」。

动效 M1–M4 仍然有效，但要挂在物件上：

- M1 对望：进门落定 / logo，不跟房间抢开场
- M2 呼吸灯：桌上那一盏，第三幕停
- M3 消息浮现：对话纸条与桌面上的痕迹，不是 Hero 里 16% 透明的装饰
- M4 消隐：毕业 + 灯灭，是全站唯一的高潮动效

全部继续尊重 `prefers-reduced-motion`。

## 8. 这一轮明确不做

- 不推倒现有品牌（夜/纸双主题、V3 logo、衬线层级、禁用词）。
- 不删九屏信息、不把第二幕改成一篇长信。
- 不全站做成三维房间或可探索空间。
- 不用视频开门。
- 不为「更像官网」增加功能区块、logo 墙、数字指标条。
- 不以补 P1–P8 截图作为本轮主任务（相纸可以先空着）。
- 不在精进里接入任何统计脚本。
- 工具页（文档、下载）不强行演戏。

## 9. 建议开工顺序

后一步可以提前做资产，但**视觉落地按这个顺序**，避免先做三维却仍是九段平铺。

| 步 | 做什么 | 完成标志 |
|---|---|---|
| 1 | 拆九屏同一骨架；压缩第三幕（信任灯旁、下载变信封、尾声接灯灭） | 滚一遍能感到「前段桌前 → 中段换物件 → 毕业后收」 |
| 2 | 第二幕物件化（拍立得 / 纸条 / 便条 / demo 纸条） | 任何一屏都不能再被认成「标题+三卡片」 |
| 3 | 2.5D 进门镜头 + 跳过 + reduced-motion 静帧 | 每次进首页可跳过；跳过后 LCP 仍在预算内 |
| 4 | 软页换纸（about / ethics / privacy / blog 的桌沿与灯） | 从首页点进软页，像换一叠纸，不像换网站 |
| 5 | 三维房间替换 2.5D 层（✅ v1.3） | 同一时间轴、同一跳过；失败可回退 2.5D |

## 10. 验收（本轮加在计划书 §10 之上）

计划书原验收（移动端、性能、SEO、双主题、伦理五条、`/go/*`）全部保留。另加：

1. **不是同一骨架**——把九屏截成九张图，不应再像同一模板换标题。
2. **有高潮**——没接触过产品的人看完，能指出「灯灭 / 字淡掉」那一段，而不是觉得每屏一样郑重。
3. **进门可逃**——首次进入 1 秒内能跳过；跳过后主 CTA 可点；reduced-motion 下无推镜头。
4. **物件可指认**——能从页上指出拍立得、纸条、信封、灯，而不是只能指出「卡片」和「按钮」。
5. **软页仍在桌上、工具页已出戏**——about 与 docs 不应长得像同一套分栏。

## 11. 房间的生产管线

房间只有一个源头：`scripts/room/build.py`（Blender 的 Python 脚本，从零搭出整间房），产物是 `assets/room/room.blend`。

```
npm run room                 # 全部重做：静帧 + 烘焙 + 压图集（M5 Max 上约 11 分钟）
npm run room -- preview      # 只出小样到 .cache/room/preview-*.jpg（几秒），调场景时用
npm run room -- stills       # 只重渲静帧 → src/assets/room/*.jpg
npm run room -- bake         # 只重烘实时三维层 → src/assets/room3d/、src/assets/room/scene.json
npm run room -- bake --from-blend   # 不重建，直接用 room.blend（在 Blender 里手工改过之后）
npm run room -- json         # 只重写 scene.json（只改了裁切对准点 CROP 这类不影响画面的参数时，几秒）
```

需要本机装有 Blender（5.1 上验证过；非默认位置用环境变量 `BLENDER` 指定）。

| 产物 | 用在哪 |
|---|---|
| `src/assets/room/room-wide(-p).jpg` | 进门第一帧、第三幕（灯亮） |
| `src/assets/room/room-dark(-p).jpg` | 第三幕灯灭 |
| `src/assets/room/desk-close(-p).jpg` | Hero |
| `src/assets/room/desk-top.jpg` | 第二幕桌面（夜） |
| `src/assets/room/desk-top-day.jpg` | 第二幕桌面（纸主题） |
| `src/assets/room3d/room.bin`、`atlas-*.webp` | 进门镜头的三维层（网格 + 光照图集） |
| `src/assets/room/scene.json` | 机位、裁切对准点、灯在画面里的位置、2.5D 推镜参数——CSS、静帧和三维层都读这一份 |

带 `-p` 的是竖幅。要注意的几件事：

- **改构图就改机位**：`build.py` 顶部的 `CAMS`（位置、转角、俯仰、焦距）。脚本会打印灯、信等锚点在每个画面里的位置，不用渲染就能调。改完静帧和烘焙都要重做（落点才对得上）。
- **镜头轨迹**由起止两个机位加一个贝塞尔控制点（`PATH_CTRL`）决定，一路盯着信附近的一点。机位不要带滚转。`build.py` 的 `path_cam` 与 `src/components/room/room3d.ts` 里的插值必须一致：整段镜头里看不到的面在导出时已经剔掉了。
- **调镜头**（仅开发服务器）：`/?intro=slow` 把时间轴放慢 40 倍；控制台里 `__room3d.scrub(0.5)` 把镜头停在任意进度。
- **成片固定 800 采样，不开自适应采样**（小样才开）。这间屋子大半是暗的，自适应会在暗处提前收手，降噪器再把剩下的噪点「脑补」成墙上一道道划痕；静帧和光照图集都一样。
- **薄片不要叠着建**：同一种材质、只差零点几毫米的几层（比如信封背面的折边）渲染里看不出来，烘进光照图却会把底下被盖住的那层黑从边缘渗出来。信封身因此只有一层。
- **半尺寸图集**（`atlas-*-1k.webp`）给竖屏和画布长边不到 1500 像素的小屏用：竖幅落点里桌子占的像素少，半尺寸已接近一比一。
- **开发服务器看不到新图？** 不会了：开发模式下静帧地址带文件修改时间（`src/components/room/fresh.ts`），重渲染后刷新即可。原因是开发服务器的 `/_image` 响应带一年的缓存头、地址里又没有内容哈希；正式构建的文件名自带哈希，不受影响。
- **贴图**来自 Poly Haven（CC0），由 `scripts/room/fetch-textures.mjs` 下载到 `.cache/`，不入库；清单见 `LICENSE-CONTENT.md`。
- **上一版的 AI 生成照片**留在 `assets/room/photo-v1/`，不参与构建，需要对比或回退时用。
