当你想在飞书里和分身对话、而手上没有公网 IP、域名或 SSL 证书时，读这篇。飞书通道用「使用长连接接收事件」（WebSocket）模式，跑在自己机器上就够。

## 开始之前

- 你在飞书企业/团队里有创建**企业自建应用**的权限。
- 长连接模式不支持商店应用——必须是企业自建应用。
- 应用需要**发布并由管理员审批**后，权限才会生效。
- Mirrai 服务端已经跑起来，网页端能正常聊天。

## 创建飞书企业自建应用

1. 打开飞书开放平台，创建一个**企业自建应用**。
2. 记下 **App ID** 和 **App Secret**，下一步要用。
3. 在应用的事件配置里开启**「使用长连接接收事件」**模式。
4. 具体要开通哪些权限与事件，以网页端「设置 → 渠道」里飞书卡片上的说明为准（不同版本要求可能调整）。
5. **发布应用**，并让管理员审批通过。

**你应该看到**：应用在飞书开放平台里显示为「已发布/已启用」，普通成员能在飞书里搜到这个应用并给它发消息。

## 在 Mirrai 里填入凭据

1. 打开网页端「设置 → 渠道」，找到飞书卡片。
2. 填入 App ID 和 App Secret（凭据加密存储，不进聊天记录、不回显明文）。
3. 点「启动」。

**你应该看到**：通道状态变成「已连接」；在飞书里给应用发一句「你好」，能收到分身的回复。找不到应用就先在飞书的搜索框里搜应用名字。

## 和网页端的关系

飞书通道与微信、网页、流式对话共用同一套对话管线（`server/chat/service.ts`）、同一套指令、同一套人设与记忆体系——加一个渠道不需要重写任何对话逻辑。

## 和网页端共享什么

- **同一套人设和记忆**：在哪边聊，TA 都记得。
- **同一套指令**：四个指令在任何渠道里行为一致。
- **同一个默认分身**：在网页端设置，飞书里用指令临时切换，切换只在当前会话内生效。
- **同一批消息**：消息带着渠道标记（web / wechat / feishu），历史和导出里能看出每句话来自哪边。

## 凭据与管理员

- App ID / App Secret 由 Mirrai **加密保存**，界面上只回显掩码，不回显明文。
- 别把凭据贴进 Issue 或聊天记录；反馈问题时先脱敏。
- 企业这边需要管理员做的只有两件：**审批应用发布**、确认应用权限已生效。

## 飞书指令

| 指令 | 作用 |
|---|---|
| `/使用 <分身名>` | 切换当前对话的分身 |
| `/分身列表` | 查看所有可用分身 |
| `/当前分身` | 查看正在对话的分身 |
| `/毕业` | 生成告别信并完成毕业 |

尖括号里换成你自己的分身名字，例如 `/使用 小雨`。

**你应该看到**：发 `/分身列表` 会回一条消息，列出你的全部分身；发 `/使用 小雨` 之后，下一句回复就换成了小雨的语气。

## 想停掉通道

在网页端「设置 → 渠道」里点「停止」。凭据和绑定关系会留着，下次直接「启动」即可，不用重新填。

## 状态一直不是「已连接」

按顺序检查这三件事：

1. **应用发布了没有、管理员审批了没有**——长连接模式下权限要等审批后才生效。
2. **是不是商店应用**——商店应用不支持长连接，必须换成企业自建应用。
3. **App ID / App Secret 是否填对**——去开放平台的应用凭证页再核对一遍。

都没问题还是连不上，把网页端通道卡片上的状态文案记下来，到 [GitHub Issues](https://github.com/Ch1rpys/Mirrai/issues) 反馈。其他常见现象见[我遇到了问题](/docs/faq)。
